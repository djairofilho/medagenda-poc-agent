# MedAgenda 3.1 — observabilidade com Langfuse

Esta versão amplia a observabilidade dos turnos de conversa e as avaliações sintéticas da POC. A reserva continua exigindo um horário cadastrado, dados válidos e confirmação explícita.

## Destaques

- Traces no Langfuse SDK Python v5 preservam sessão anonimizada, tipo de observação, modelo e uso de tokens. Prompts, respostas e conteúdo clínico são removidos antes da exportação.
- Cada turno registra rota, fase, resultado da tentativa de reserva e sucesso técnico. Falhas aparecem por categoria controlada, sem mensagem nem stack trace sensível.
- Scores objetivos de sucesso técnico e integridade da reserva ficam vinculados ao trace.
- Quatro prompts gerenciados, para classificação, extração, informação e triagem, usam o rótulo `production`, cache de cinco minutos e fallback local nos dois adaptadores de modelo.
- As evals determinísticas cobrem resultados de reserva, turnos consecutivos e fallback dos prompts. O CI valida PostgreSQL e SQLite; experimentos com modelo real e publicação continuam manuais ou agendados.
- O [guia de monitoramento](https://github.com/djairofilho/medagenda-poc-agent/blob/3.1/docs/observability.md) descreve os widgets e alertas para recriação na interface do Langfuse.

## Configuração

Defina `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` e `LANGFUSE_TRACING_ENVIRONMENT=production` para habilitar traces e filtrar o painel de produção. Para publicar as versões iniciais dos prompts no projeto configurado, execute manualmente:

```powershell
uv run --locked python -m scripts.publish_prompts --publish
```

Sem versões acessíveis no Langfuse, os adaptadores usam os prompts locais. Siga o [README](https://github.com/djairofilho/medagenda-poc-agent/blob/3.1/README.md) para iniciar a aplicação e executar as evals.

## Limites da POC

Esta versão não configura automaticamente a conta Langfuse nem publica prompts no CI. A aplicação continua sendo uma POC com dados fictícios, sem autenticação para uso com pacientes reais.
